# 云端目录快照核心

2026-10-24 用户选择七牛 Kodo + 版本化目录快照，不引入数据库。此包负责目录提交；SCF 的完整云端 API、直传、异步抓取和迁移工具通过它提交可见状态。部署流程见 [云端部署说明](../../docs/cloud-deployment.md)。

## 唯一权威与提交点

`<prefix>/00000000000000000000.json` 是初始目录。之后每个连续整数版本存一份完整快照，包含目录节点、任务和操作回执。Kodo 对快照做 gzip，读取兼容已有未压缩 JSON。节点 ID 不随路径改变；数据对象 key 独立于可见文件名。

每次操作读取当前版本 N，在内存中产生 N+1，使用限定到**单个 key** 的七牛上传凭证和 `insertOnly: 1` 创建 N+1。这个对象创建是唯一提交点。竞争者收到 614 后，读回已提交版本并重新验证操作。没有覆盖 `head.json`、分布式租约或依靠 SCF 实例内单队列。

`Current` 通过精确对象存在性查询、指数探测和二分定位最新连续版本，最后读取选中快照；不支持 Exists 的 Store 使用精确 GET，不依赖桶列举顺序。实例内的版本号只是单调提示；调用者可传 `minRevision`，防止落后于已经看到的提交。平台暂时读不到必需版本时直接失败，不退回空目录。精确 GET 的可见性仍影响读请求的新鲜度；禁止将这轮有限实测表述成厂商对任意网络、地域的线性一致性保证。

写入竞争失败后必须读回争用版本，避免反复使用落后的读取结果。创建回执丢失属于结果未知：返回错误，调用者用**同一个操作 ID 和参数**重试，从快照恢复原回执；不能换 ID 重做。

## 操作语义

- `mkdir`、`publish`、`move`、`copy`、`delete` 都在一份快照中提交，整棵子树只显示提交前或提交后的状态。
- 同名按 `name(1).ext` 续号，编号分配在快照提交竞争内完成。
- 操作 ID 与账号、全部参数绑定。成功和语义拒绝均保留回执；换参数复用 ID 会报错。
- 上传准备阶段绑定 `ParentID`。父目录改名后，完成上传归入同一个目录的新路径；父目录删除后，即使同名新建，也拒绝旧上传。
- `publish` 只接受已经由上层检查过存在性、大小、七牛哈希的不可变对象描述。本包**不会替上传完成函数验证桶内对象**；整文件 xxhash、图片内容哈希和七牛哈希仍是不同概念。
- `copy` 复制目录节点并共享不可变数据对象；`delete` 仅断开节点引用。阻止根目录操作、目录环及非法名称。

## 当前保留边界

**不回收历史快照或回执。** 连续版本定位和丢回执恢复依赖它们，不能给 snapshots 配自动过期。目录删除只断开引用；云端维护器在至少七天后，结合当前完整引用、未过期任务和不可变对象唯一分配规则回收无引用数据，不能把目录删除直接实现为删 blob。历史快照不承诺被删除数据的永久保留。

单份解压快照上限 32 MiB，容量不足返回 507。真实全库 10,394 节点：JSON 2,998,212 字节，gzip 1,207,683 字节。每次写上传完整压缩快照，回执持续累计；元数据历史压缩/检查点仍须新协议，不能假称可无限增长。

真实目录元数据必须放私有桶，禁止在现有公开前端桶写入真实目录或文件信息。`catalog-probe` 在指定桶只写无真实数据的随机测试前缀，完成后清理自己生成的对象。

## 验证

```sh
go test ./internal/catalog
go run ./cmd/catalog-probe --bucket TEST_BUCKET \
  --credentials-file /path/to/qiniu-keys.env \
  --output /tmp/catalog-probe.json --workers 4 --yes
```

凭证文件沿用 `QINIU_AK` / `QINIU_SK` 格式，不输出、不入包。云端探针验证多个独立目录客户端竞争、真实提交后注入响应丢失、同 ID 重试、删除后迟到上传和持久拒绝回执；它们与生产 API、真实导入是不同验收阶段。
