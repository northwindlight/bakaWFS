## 已确认的目标

- 原生产源站 `www.northwind.site` 因电源损坏不可用；不能把恢复该主机作为迁移前提。
- 漫画数据放七牛 Kodo，核心运行在腾讯云函数 SCF，前端继续由对象存储/CDN 托管。
- 上线后不依赖 Raspberry Pi、Windows 源站或其他自管常驻主机。本机只作为本次数据导入和以后可选的开发工具，不承担线上管理 API、队列或权威目录状态。
- 用户已明确选择完整在线管理：浏览、搜索、阅读、上传、改名、移动、复制、删除、新建目录，不能以只读书库代替交付。现有远程 URL 下载及任务进度/取消需在迁移范围内明确安排。
- 调用模型是浏览器主动请求 URL，触发相应函数，函数鉴权后执行控制操作。文件数据由浏览器直传存储桶；上传结束后浏览器再次调用完成接口，函数检查桶、完成分片合并及提交。
- 这里不是浏览器接收 webhook 的模式。七牛回调可以作为补充，但不作为前端完成上传的唯一通知方式。
- 用户要避免长 HTTP 请求等待文件传输完成。短函数调用可以直接返回结果；不要自行把所有操作扩展为消息总线、后台队列、WebSocket 推送或回调编排。

## 用户确定的调用流程

### 上传

1. 浏览器调用准备上传函数；函数验证用户、角色、目标目录和参数。
2. 返回短期、限定对象/操作范围的七牛上传凭证，以及可关联后续提交的操作号或签名票据。
3. 浏览器直接向七牛上传文件/分片，负责本地进度展示和可用的断点恢复。
4. 浏览器调用完成上传函数，再次鉴权；不能只信“客户端说上传完了”。
5. 函数核对操作归属、对象/分片存在性、大小和约定的校验信息；采用七牛原生分片完成/合并能力，不把整文件搬进 SCF 拼接。
6. 验证成功后提交目录可见结果，再返回最终路径/对象标识和提交结果。
7. 浏览器刷新目录；完成调用超时或响应丢失时，用同一操作号重试，得到同一个提交结果。

“七牛上传完成”与“文件已经在站点目录中发布”是两个阶段。分片失败、合并失败、校验失败、目标目录已被删除等情况不能留下半个可见文件。七牛 ETag、整文件 xxhash、漫画像素哈希不是同一种校验值，不可混用。

### 改名、移动、删除、复制、新建目录

浏览器调用对应函数 → 函数鉴权/验证目标 → 提交操作 → 返回回执。短操作直接完成，不为了“函数化”强制做成异步任务。

- 目标同名冲突继续有明确且可重复的处理结果，不能重试一次就多出一个副本。
- 目录移动/删除须保持整棵子树原子可见；不能用逐对象循环冒充原子事务。
- 复制、物理回收等若确实超出一次函数时限，再使用可恢复任务和结果查询。浏览器关闭后，已接受的任务不能依赖该页面继续驱动才完成。
- 取消语义区分“停止未提交工作”与“撤销已提交结果”；不能把响应中断当作撤销成功。

### 浏览、登录、阅读

- 登录与查询可以是短请求/响应函数；保留 admin/guest 分级和所需的登录门槛。
- 列目录、全库搜索必须看到同一套目录权威状态，不逐次从失去逻辑改名关系的对象 key 猜测。
- 函数签发适当的对象访问地址，图片/视频/普通文件经七牛/CDN直接传输，保留 Range、文件下载与预览能力。
- 公开前端所在桶的访问方式不自动等于漫画数据的访问方式；迁移要明确原图及目录是否仍要求登录，不能悄悄把登录门槛变成纯前端隐藏。

## 首先要定的核心：目录原子提交

补充调研：[对象存储选型比较](object-storage-comparison-20261018.md)。用户要求跨厂商比较，存储供应商尚未最终锁定；原提案是七牛，核心已定腾讯SCF。腾讯COS元数据加速桶、OSS分层命名空间、OBS并行文件系统存在真实目录能力，不能继续假定所有桶都没有原子Rename。先验证特殊桶的账号/地域、CORS直传、CDN及图片处理限制；若能直接满足需求，应优先比较是否可避免自建权威目录映射/事务层。旧普通桶方案作为兼容备选，不立即落地。

这是下一次工作的第一个设计关口，尚未拍板，不先选数据库或开始搬库。

对象 key 按可见路径组织时，整目录移动/删除需要多个对象操作，HTTP 触发云函数并不会自动把它们变成事务。原有进程内串行队列也不能跨 SCF 实例协调；降低并发不等于获得持久化、重试及崩溃恢复语义。

候选方案：

| 方案 | 能力与代价 | 下一步 |
|---|---|---|
| 对象 key 直接作为目录状态 | 简单，无独立映射；多对象目录操作无法直接满足现有原子语义 | 不作为默认交付方案 |
| 不可变数据对象 + 有事务的目录元数据 | 改名/移动修改目录节点；删除先切断可见入口，再回收对象 | 评估托管元数据服务、事务能力、费用及运维复杂度；引入数据库须明确讨论 |
| 不可变数据对象 + 版本化目录快照 | 无独立数据库，目录快照本身是权威数据；通过发布新版本切换可见树 | 必须先实证条件提交/冲突检测、并发写入、崩溃恢复和读一致性，不能简单覆盖 head.json |

若采用元数据映射，必须明确它是目录的唯一权威，不同时维护“对象 key 路径”和另一套目录映射作为双重真相。不要把权威目录当作可随意重建的缓存。

需要明确的提交语义：

- 每次操作有稳定的幂等标识，权限和参数绑定；重复调用返回原结果。
- 多个实例同时写入时，冲突可检测、可重试，不出现丢更新或名字冲突。
- 文件夹移动不产生环；对正在上传的目录执行移动/删除时，完成上传的归属规则明确。
- 已提交的删除不会被迟到的完成上传/回调“复活”。
- 垃圾回收只删除确认无引用的对象，兼顾失败上传、复制共享内容、读者仍持有的旧地址和回滚窗口。
- 目录提交成功后，即使回执丢失也能查询到结果；清理失败不回滚成半棵目录。

## 语言与运行形态

暂不决定重写为 JS/Python。腾讯云官方有 Go 事件函数入口：`cloudfunction.Start(handler)`，与启动 HTTP Server 的 Web 函数形态不同。二进制部署不妨碍事件函数语义。

下次先确认目标地域/账号可选的当前运行时、SDK、打包方式和冷启动，再做最小 Go 事件函数验证。只有平台实际限制或开发维护收益足够明确时，才讨论更换语言；不因“Go 只能微型虚拟机、不能函数调用”的假设直接重写。

现有鉴权、角色、校验、漫画识别/阅读 UI 可按实际耦合复用；文件操作队列、落盘 chunk、路径扫描、远程下载 worker 和修改图片元数据的本地流程不能原封不动搬上 SCF。

## 冷启动与语言选择的验证计划

用户补充关切：Go 是否每次纯冷启动，而 Node.js 能复用预热进程，从而值得承担重写成本。该假设需先核实，不作为选型结论。腾讯 SCF 工作原理描述实例复用；[CloudBase 官方实例说明](https://docs.cloudbase.net/cloud-function/instance)也明确 Node.js 示例所述机制适用于 Python/PHP/Go/Java。不能把 Go 二进制部署等同于每次从零启动，也不能把 Node.js 的机会性热实例当作永远预热的保证。

下次做对照验证时：

- 同地域、同内存/架构、同入口与网络条件，分别部署最小 Go/Node.js 事件函数；记录初始化时生成的实例标识、进程标识和初始化次数，确认连续调用是否复用。
- 区分新实例冷调用、连续热调用、闲置后调用和突发扩容；通过平台日志确认是否冷启动，不能仅凭等待一段时间推断实例已回收。
- 先测空处理函数，再测同等鉴权/JSON处理和同一七牛元信息请求；将冷初始化、业务执行与端到端网络耗时分开，记录分位数及样本数，不拿空函数平均值代替真实操作延迟。
- 比较无预置并发的基线；如考虑预置并发，单独比较收益与额外费用，不默认启用付费常驻预热。
- 只有真实业务延迟差异足够显著，且确认来自语言/运行时而非部署形态或网络，才重新评估重写；目前保留 Go 为先验证方案，不宣称 Go 或 Node.js 必然更快。

2. **建立函数适配与最小闭环。** 在现有统一代码线上实现登录、目录查询、准备上传、浏览器直传、完成提交、读取；部署到测试入口/隔离前缀，不先切旧站入口。按需要定义事件/请求结构和错误回执，不预设一操作一部署单元。
3. **补齐管理语义。** 改名、移动、删除、复制、新建目录及冲突处理；验证并发、幂等、迟到请求和原子可见性。远程 URL 下载、进度和取消采用适合云端的执行/恢复机制。
4. **缩略图与前端适配。** 复用现有漫画语义、海报墙、搜索和阅读器；原图/缩略图走七牛直连。本地生成或云端生成的方案待定；不得依赖 RPi 常驻生成。迁移阶段保持 `/opt/漫画` 原档不变，需预处理时用临时副本，复用现有 hash/thumb 实现，不另造冲突格式。
5. **导入整库。** 只读重新盘点 `/opt/漫画`，记录路径、类型、大小和内容校验，识别硬链接/重复内容/隐藏元数据。断点续传导入到隔离前缀，核对对象存在性、大小和校验结果，再发布目录；不把爬虫日志、凭证或不需要公开的内部元数据直接暴露。保留本地原档及迁移报告。
6. **修复静态部署工具。** 当前 `qiniu-tool/deploy.go` 上传按字典序 keys，必须改为先上传并确认全部带哈希依赖，再最后发布 index.html；入口缓存策略与 CDN 刷新也要验证。保留旧哈希资源用于旧页面和回滚，处理哈希碰撞/引用缺失。新前端由统一源码生成部署配置，避免再养一份手工漂移的七牛版本。
7. **线上测试与切换。** 完整验收隔离版本后，切换 `cloud.northwind.site` 的前端/API配置，刷新入口，验证实际 CDN 页面的版本和所有请求目的地；保留上一版入口以便回滚。迁移新资源不依赖已损坏的 www，也不把本机 IPv6 API作为临时“最终方案”。
8. **记录和交付。** 更新 README、部署脚本、归档上线总纲、记忆入口；明确 main 的合并/发布状态、账号管理方式、后续浏览器上传与本机可选批量导入的方法，记录实际账单计费项与保留/回收策略。

## 验收标准

- 本机只作为测试客户端时，线上所有业务请求仍不访问 www 或 RPi 的服务；站点运行不依赖它们在线。
- 访客/guest/admin 权限符合约定；没有把七牛或腾讯长期密钥放进公开静态资源。
- 浏览器直传、小文件与分片上传、丢失完成回执后的重试、取消/过期清理均有真实测试。
- 整目录改名/移动/删除在并发读写和故障注入下符合选定的原子提交契约；不是只看 API 返回成功。
- 搜索、海报、缩略图、渐进阅读、特殊字符路径、下载/Range 和手机界面全部可用。
- 迁移报告将源目录清单、实际发布目录、远端对象大小和校验对应起来；去重后的对象数量可以不同，但每个发布文件必须可追溯。
- 静态发布中途失败不会发布缺少依赖的新入口；缓存中的旧页仍能加载对应旧资源。
- 在线管理正常、失败操作可恢复，新增数据不会因回滚前端而丢失。本地归档不因迁移被删除或重写。
