# 统一维护

## 原因与落点

原 main/manga 含大量内容相同、提交编号不同的 cherry-pick，公共修复缺少共同汇合点。此次以包含漫画功能及本地搜索海报墙提交的 manga 为起点，对照 main 确认公共后端无功能缺失，把漫画差异收敛为 `manga_mode` 显式配置。普通模式不注册任何可执行缩略图生成的行为；直接请求相关路径返回 404，预生成命令也要求开关。

目标：后续全部功能与修复进入 main，单一 v* 发行；manga 保留已有历史及旧发行，不再持续维护。无需删除或改写原分支，不强推。合并统一维护分支后，再让 main 成为唯一工作入口。feature/storage-abstraction 仍是独立设计草案，本次不接入。

## 部署迁移

1. 保留现有配置、用户、文件与缓存；配置不入 Git。
2. 漫画部署明确添加 `manga_mode: true`；普通部署保持默认 false。
3. 确认文件区与删除暂存区同盘、暂存区不公开且可写。文件根为挂载点或软链时按 README 配置。
4. 外置前端同步全部文件，保留部署特定的 API_BASE；公开运行库已随 html/vendor 提供，无须复制本地字体；内置前端随二进制一起更新。
5. 本地验证后按现有方式停止旧服务、替换二进制再启动；本次维护未部署生产、未修改现有运行配置。

## 回归约束

- 默认模式请求缩略图不得改写原图，也不得偷偷生成缓存。
- 漫画模式保留图片元数据嵌入，前端展示不再依赖分支。
- 删除的提交点只有 rename，禁止跨盘 copy/remove 回退；后台清理失败不能把原路径恢复成半棵目录。
- CI 同时运行 Go 测试与真实浏览器两模式回归；发行说明直接来自提交列表，不再依赖外部模型服务或省略 bug 修复。

## 前端依赖

package.json 与 package-lock.json 锁定运行库和构建/测试工具。`npm ci && npm run build:ui` 从 npm 包复制 Vue 生产版、xxhash-wasm 及许可证，并用 Tailwind 4 编译静态 CSS；产物随 Go embed/外置前端交付。不要复制 rpihtml/vendor 的 Segoe 字体等不可公开分发资源。没有外部 CDN、Google Fonts 或浏览器运行时 Tailwind 编译器。

Tailwind CLI 4.3.3 固定的 @parcel/watcher 2.5.1 间接引入有公告的 braces。package.json 将 watcher 覆盖至同主版本 2.6.0，构建与浏览器回归通过后保留该覆盖；后续上游解除固定版本时可再移除。
