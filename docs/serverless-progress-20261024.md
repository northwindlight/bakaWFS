## Go / Node 对照

同地域、128 MB、事件函数、无预热，分别发布 3 个新版本，首次和第二次调用由平台 `Init Report` 与实例 ID 交叉核对。各组第一次执行出现 Coldstart，第二次使用相同实例 ID、序号为 2，日志不再出现初始化报告。

| 指标 | Go1（Go 1.25 编译） | Nodejs20.19 |
|---|---|---|
| 平台确认的 3 个冷启动样本 | 49 / 50 / 48 ms | 106 / 102 / 101 ms |
| 同版本第二次复用 | 3/3 | 3/3 |
| 函数 URL 连续请求数 | 30 | 30 |
| 本机网络端到端 p50 / p95 | 41.335 / 67.448 ms | 47.888 / 93.054 ms |

这些是**空处理探针、有限样本**，未覆盖完整鉴权 + 七牛请求、长时间闲置及多网络读图，不能作为语言通用性能排名。它们足以否定“Go 每次都重新冷启动、Node 才能复用”的假设；本阶段保留 Go，复用现有代码。HTTP 连续采样尝试复用连接，突发采样另建连接并单列，未将两者混算。

证据：[平台初始化回执](evidence/serverless-20261024/platform-runtime.json)、[HTTP 全部样本](evidence/serverless-20261024/http-runtime.json)、[鉴权回执](evidence/serverless-20261024/bootstrap.json)。

## 对象存储边界：为什么没有直接采用 COS 路径树

旧国际页仍把 CORS 标为不适用，不能据此排除特殊桶。2026-07-14 的[国内元数据加速说明](https://cloud.tencent.com/document/product/436/56971)已明确支持 CORS。本轮按官方 [COSCLI 的 OFS 创建参数](https://github.com/tencentyun/coscli/blob/master/cmd/mb.go)创建私有空测试桶，HEAD 返回 `x-cos-bucket-arch: OFS`，实际验证该账号可创建，未遇白名单拒绝。

- CORS 配置、预检以及真实 Chromium 跨域 PUT 成功；浏览器可读 ETag。
- 原生 `PUT <destination>?rename` 携带 `x-cos-rename-source` 可移动整目录；并发抢同一源目录，结果为 1 次 200、1 次 404。
- 先 Rename 到私有垃圾前缀，再递归清理的流程通过。此处只验证提交前后目录及各文件状态，没有声称两次独立读请求可以取得同一时刻的跨路径快照。
- **失败用例 1：** Rename 到不存在的父目录仍返回 200 并重建目录，简单“检查目录后再 Rename”不能阻止删除后的迟到提交。
- **失败用例 2：** 本次 OFS 桶对带 `x-cos-forbid-overwrite: true` 的同 key 8 个不同内容并发 PUT 全部返回 200，不能拿它作为快照的单赢家创建原语。这一观察只针对本次 OFS 配置，不能外推到普通 COS 桶。
- **七牛对照：** 限定单 key 的 `insertOnly: 1`，8 个不同内容并发上传仅 1 次成功，其余 7 次 614；胜出对象大小为预期的 24 字节，探针对象已删除。上传策略语义见[官方文档](https://developer.qiniu.com/kodo/manual/1206/put-policy)。

据此向用户列出选型后，用户明确选择七牛 + 不可变目录快照。没有把 COS “能 Rename”或七牛单个测试成功夸大为完整业务语义已经完成。

证据：[OFS 与浏览器测试](evidence/serverless-20261024/ofs-capabilities.json)、[七牛单 key 竞争](evidence/serverless-20261024/kodo-insert-only.json)、[目录核心真实提交](evidence/serverless-20261024/catalog-kodo.json)。

## 日志与资源收尾

SCF 默认会接入 CLS。[官方说明](https://cloud.tencent.com/document/product/614/105512)指出，停止采集后旧日志仍有存储费用。本轮发现函数自动绑定的是 2025 年已有的共享主题，先停止采集；用户明确选择删除该主题及历史数据后，已调用 DeleteTopic 并确认主题不再出现在列表中。不是只把调用参数 `LogType` 改为 None，也不是只静默应用日志。

保留的 Go 引导函数默认关闭应用日志输出，`BAKAWFS_LOG_ENABLED=true` 才启用；平台已读回确认 `ClsLogsetId`、`ClsTopicId` 均为空，`IgnoreSysLog=true`。更新最终测试包并实际请求 `/healthz` 后，再次查询 CLS 主题数仍为 0。之后创建或更新测试函数，也必须检查平台是否重新接入默认 CLS，不以“没有写日志配置”推断不收费。日志清理证据见 [回执](evidence/serverless-20261024/logging-cleanup.json)。

两个运行时探针函数已删除。COS 测试文本已清理、空桶删除请求已接受；该类桶后端异步删除，不能把请求成功立即当成 HEAD 已不存在。Go 鉴权引导函数暂留为后续接线入口。云端资源精确名称、测试账号和临时上传票据仅保留在本机忽略的 `dist/scf/` 或临时操作记录，不纳入公开证据。
